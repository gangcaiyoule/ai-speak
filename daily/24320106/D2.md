## 遇到的问题与解决

1. **协作平台和流程与课程要求不一致。** 仓库原先按 GitHub 习惯配置，Issue 编号又是 Gitee 企业项目的字符串格式。通过更新 `AGENTS.md`、Issue Skill 和新增 PR Skill，统一改为 Gitee API、`gitee/main` 和 PR 目标 `main`，并在 PR 中使用 `Closes #<编号>`，再通过 Issue/PR 两侧接口核对关联结果。
2. **Practice 页面容易把网络请求和页面状态混在一起。** 将流程拆成 `Practice 页面 -> PreparationController -> SceneClient -> WireSceneClient -> HTTP API`，由 Controller 统一处理加载、空列表、失败重试、详情版本校验和角色切换后的不兼容选项清理，页面不直接访问 HTTP。
3. **语音接口的“采样率”和时间戳不能简单当成平台保证值。** 对照平台文档后，将 iOS 采样率表述为请求值并要求激活后读取实际值；Oboe 不支持 `getTimestamp()` 时回退到本地单调时钟。这些限制已写入接口文档，避免后续实现依赖错误前提。
4. **本机没有 Flutter SDK。** Go 侧已执行并通过 `go test ./...`、`go vet ./...`、`go build ./...`；Flutter 的安装、分析和测试交给 Gitee CI 容器执行，日报中保留该验证边界，不把未在本机执行的检查写成已完成。
