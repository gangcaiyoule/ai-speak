## 遇到的问题与解决

1. **模块边界尚未清晰。** 先按 identity、agent、coaching 三个领域拆分客户端和服务端接口，将 HTTP 适配、领域模型和 Stub 分开，降低后续接入真实服务时的改动范围。
2. **不同模块需要统一错误和请求处理方式。** 通过各模块独立的 HTTP handler 及测试骨架约束响应结构，先保证接口可以被单独验证，再继续实现业务逻辑。
3. **CI 配置与本地环境存在差异。** 本机未确认 Flutter SDK 可用，因此没有把 Flutter 检查写成本地已通过；Go 检查由 GitHub Actions 负责，后续需结合 CI 结果继续修正配置。
