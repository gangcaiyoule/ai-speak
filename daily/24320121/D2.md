## 遇到的问题与解决

1. **本机没有任何验证环境**（无 Flutter/Docker/WSL），R1 代码提交后一直处于「手工推演过但没跑过」状态。解决：GitHub Codespaces。这条路上连续踩了三个坑，每个都有明确症状和解法：onCreateCommand 里现场 git clone SDK 导致创建阶段卡死 → SDK 打进镜像；`gh codespace ssh` 报 failed to start SSH server → 镜像里缺 `ghcr.io/devcontainers/features/sshd:1`；Windows 新版 OpenSSH 下 `gh codespace cp` 报 dest open No such file or directory → 强制 scp 协议加 `-- -O`。全部记进指南的踩坑记录一节。
2. **代码在本地、环境在云端的闭环问题**：改动怎么过去、结果怎么算数？定下「本地 commit → push fork 分支 → `gh codespace ssh` → `git pull --ff-only` → 跑 analyze/test」的标准流程写进指南，之后每次提交都照此执行，R3 的 32 个用例就是第一批按这个流程出的真实验证。
3. **会话适配层两个并发缺陷**：waiter 空断言、超时后事件被重复完成。这类问题单靠肉眼review很难发现，靠的是给 session 状态机补了 12 个时序用例，跑出来才暴露。
4. **FFI 边界的签名与内存释放不一致**：Dart 侧绑定签名和 C ABI 对不上、释放责任不清晰。解法是双端收敛到同一份 C ABI 头文件（`native/voice_input.h`），Android/iOS 共用，Dart 侧按它重新对齐签名并明确谁申请谁释放。
5. **stop() 阻塞在无人订阅的流上**：采集停止路径会被没有订阅者的 Stream 卡住。改成 stop 不等待订阅，并同步修正 gap 测试的时序假设。
