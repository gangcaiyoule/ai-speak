## 2. 设计依据与范围

本设计依据以下信息整理：

1. 个人职责图：负责场景列表、场景详情、练习目标设置、场景配置和练习计划管理；不负责实时问答、语音处理和练习报告生成。
2. 仓库当前状态：场景选择闭环已经完成；练习会话相关路由仍返回 `not_implemented`；数据库迁移机制已经存在。
3. 当前需求清单：推进 R6 创建/查看/激活/完成练习会话、R7 文本回答、R11 PostgreSQL 持久化和 R12 Flutter 练习页面。

本次只设计以下链路：

```text
登录
  -> 场景列表
  -> 场景详情、角色和模式选择
  -> 设置练习目标
  -> 创建练习计划
  -> 创建并激活练习会话
  -> 查看当前问题
  -> 提交文本回答并推进问题
  -> 完成练习会话
  -> 查看会话最终状态
```

本次明确不做：

- LLM 动态出题和 Agent 对话线程；
- 麦克风录音、ASR、TTS、WebSocket 和实时语音；
- 评测报告生成、结果页和历史复盘页；
- 简历上传、岗位描述解析和复杂练习计划推荐。

## 3. 设计目标

### 3.1 主要目标

- 形成一条从场景选择到文本练习完成的可运行纵向链路。
- 让计划、会话、问题和回答能够持久化，并且按登录用户隔离。
- 用明确的状态机阻止非法操作，错误尽早暴露。
- 通过一个小的应用模块隐藏状态转换、问题推进和数据保存细节。

### 3.2 模块设计原则

练习模块以 `PracticeService` 作为主要接口，调用方只需要提交用例输入，不直接操作数据库或修改状态。数据库使用两个 Adapter：

- `MemoryRepository`：用于快速单元测试；
- `PostgresRepository`：用于正式运行和手工演示。

二者共享同一个 Repository Interface，形成清晰的 Seam（接缝）。状态校验、用户隔离和问题推进放在 Service Implementation 内部，保持调用方简单，并提高模块的 Depth（深度）、Leverage（复用收益）和 Locality（修改局部性）。

## 5. 状态机

### 5.1 练习计划

```text
DRAFT -> ACTIVE -> ARCHIVED
```

- 创建计划后为 `DRAFT`；
- 创建会话并开始练习时将计划置为 `ACTIVE`；
- 计划归档后不可创建新会话；
- 已归档计划只读。

### 5.2 练习会话

```text
DRAFT -> ACTIVE -> COMPLETED
```

- 只有 `DRAFT` 会话可以激活；
- 只有 `ACTIVE` 会话可以提交文本回答；
- 只有 `ACTIVE` 会话可以完成；
- `COMPLETED` 会话只读；
- 所有非法状态转换返回明确错误，不自动修复或静默忽略。

### 5.3 回答推进规则

1. 校验会话属于当前 Token 对应用户。
2. 校验会话状态为 `ACTIVE`。
3. 校验提交的问题是当前问题。
4. 校验回答去除首尾空白后非空且不超过约定长度。
5. 保存回答并将当前问题改为 `ANSWERED`。
6. 若存在下一题，将 `current_question_id` 指向下一题；否则允许完成会话。

## 6. 服务端模块设计

### 6.1 模块与接口

建议在 `server/internal/coaching/practice/` 中扩展以下模块：

- `model.go`：计划、会话、问题和回答模型；
- `ports.go`：PracticeService 和 Repository Interface；
- `service.go`：创建计划、创建会话、激活、回答和完成逻辑；
- `memory_repository.go`：测试用内存 Adapter；
- `postgres/repository.go`：PostgreSQL Adapter；
- `service_test.go`：状态机、权限和问题推进测试。

服务接口应覆盖以下用例：

```go
CreatePlan(ctx, actorID, input) (Plan, error)
ListPlans(ctx, actorID) ([]Plan, error)
GetPlan(ctx, actorID, planID) (Plan, error)
ArchivePlan(ctx, actorID, planID) error
CreateSession(ctx, actorID, planID) (Session, error)
GetSession(ctx, actorID, sessionID) (SessionView, error)
ActivateSession(ctx, actorID, sessionID) (SessionView, error)
SubmitTextAnswer(ctx, actorID, sessionID, input) (TurnResult, error)
CompleteSession(ctx, actorID, sessionID) (SessionView, error)
```

HTTP Handler 只负责解析请求、获取当前用户、调用 Service 和转换错误；不在 Handler 中实现状态机或 SQL。

### 6.2 HTTP 接口

#### 练习计划

```text
POST   /v1/practice-plans
GET    /v1/practice-plans
GET    /v1/practice-plans/{plan_id}
POST   /v1/practice-plans/{plan_id}/archive
```

创建请求示例：

```json
{
  "scene_id": "self-introduction",
  "scene_version": 1,
  "role_id": "candidate",
  "practice_option_id": "focus-communication",
  "objective": "练习用英文清楚介绍我的项目经历"
}
```

#### 练习会话

```text
POST   /v1/practice-sessions
GET    /v1/practice-sessions/{session_id}
POST   /v1/practice-sessions/{session_id}/activation
POST   /v1/practice-sessions/{session_id}/text-answers
POST   /v1/practice-sessions/{session_id}/complete
```

创建会话请求只传计划标识：

```json
{
  "plan_id": "00000000-0000-0000-0000-000000000001"
}
```

提交回答请求：

```json
{
  "question_id": "00000000-0000-0000-0000-000000000002",
  "content": "I worked on a mobile application for ..."
}
```

### 6.3 错误码

至少统一支持以下错误：

| HTTP 状态 | 错误码 | 场景 |
|---:|---|---|
| 400 | `invalid_request` | 字段缺失、格式错误或回答为空 |
| 401 | `authentication_required` | 缺少或无效 Token |
| 403 | `forbidden` | 资源不属于当前用户 |
| 404 | `resource_not_found` | 计划、会话或问题不存在 |
| 409 | `invalid_state_transition` | 非法状态转换或重复回答 |
| 500 | `internal_error` | 数据库或不可预期错误 |

## 7. PostgreSQL 设计

新增迁移文件，例如：

```text
server/migrations/0005_practice_plans.sql
server/migrations/0006_practice_sessions.sql
```

迁移至少创建以下表：

- `practice_plans`；
- `practice_sessions`；
- `practice_questions`；
- `practice_turns`。

约束要求：

- 主键使用 UUID；
- 计划、会话和回答必须带 `actor_id`；
- 会话引用计划；问题引用会话；回答引用问题；
- 状态使用数据库 `CHECK` 约束；
- 问题位置在同一会话内唯一；
- 同一问题只能有一条首版回答；
- 为 `(actor_id, updated_at)`、`(actor_id, status)` 建立必要索引；
- 外键删除策略避免误删历史练习记录。

服务启动时读取 `DATABASE_URL` 并连接 PostgreSQL。正式运行不自动回退到内存数据库；连接或迁移失败直接报错。单元测试通过依赖注入使用 `MemoryRepository`，避免测试依赖外部数据库。

### 8.2 页面流程

现有场景详情页点击“开始练习”后：

1. 进入练习准备页；
2. 自动带入场景、角色和练习模式；
3. 用户填写练习目标；
4. 点击“创建练习计划”；
5. 创建成功后显示计划摘要和“开始会话”；
6. 创建并激活会话后进入练习进行中页；
7. 显示当前问题和多行文本输入框；
8. 点击“提交回答”后刷新下一题；
9. 最后一题提交后允许点击“完成练习”；
10. 完成后展示会话已完成状态，并提示后续评测功能尚未接入。

页面只负责展示状态和派发用户操作；状态转换由 Controller 调用客户端 Interface 完成。

## 9. 测试与验证计划

### 9.1 Go 单元测试

- 创建计划成功和参数校验；
- 只能读取当前用户自己的计划；
- 归档后不能创建新会话；
- 创建会话生成正确数量和顺序的问题；
- `DRAFT -> ACTIVE` 激活成功；
- 非 `DRAFT` 会话重复激活失败；
- 只有 `ACTIVE` 会话能提交回答；
- 非当前问题回答失败；
- 提交回答后正确推进到下一题；
- 最后一题完成后会话进入 `COMPLETED`；
- 已完成会话不能再次回答或完成；
- HTTP 层返回正确状态码和错误码；
- PostgreSQL Adapter 的关键查询和迁移可在本地数据库验证。

### 9.2 Flutter 测试

- 计划创建中的加载、成功和失败状态；
- 目标为空时禁用提交；
- 创建成功后正确进入会话页；
- 回答提交期间防止重复点击；
- 服务端错误能显示并允许重试；
- 会话完成后显示最终状态。

## 11. 验收标准

本设计对应的实现满足以下条件时，才算达到今天的目标：

- 登录用户能够创建并查看自己的练习计划；

- PostgreSQL 中能够查到计划、会话、问题和回答；

## 12. 风险与降级方案

- 若 PostgreSQL 接入耗时过长：先完成 Service、内存 Adapter、迁移文件和接口测试，再单独完成 PostgreSQL Adapter；不伪称持久化已验证。
- 若 Flutter SDK 不可用：完成 Dart 代码和测试设计，保留 Go HTTP 成功链路和接口示例，并在日报中写明未执行项。
- 若时间不足：优先保证“创建计划 -> 创建会话 -> 激活 -> 提交回答 -> 完成”的 Go 链路；计划归档和 Flutter 视觉细节可以延后。
- 不接入动态 Agent、语音和评测模块，避免与队友职责重叠以及扩大 Issue 范围。
