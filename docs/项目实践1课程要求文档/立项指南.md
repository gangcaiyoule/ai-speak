# 立项指南

## 立项要求

- 由5人(如有特殊情况，须给出充分理由并报教师批准)组队，并推选出组长一名。
  - 注意：不允许跨班级。本次课程一共有三个教学班（不同教师），组队只允许在同一教学班即同一教师名下
- 题目自拟，主题应健康向上，内容真实且丰富，与个人兴趣、校园生活、当前时代等有相关性。不可以是主题消极有害，内容干瘪，完全与本人无关。
- 技术主题：以一个Web项目为基准，涵盖前端、后端、数据建模或算法、数据管理、部署与运维、项目管理等
  - 前置课程：《Web前端技术》、《Web程序设计》、《软件工程》、《数据库应用》、《数据分析与建模》或《机器学习》等
- 技术难度：能反映所处年级所学各课程的技术知识及工具能力
- 项目工作量：按64小时（课内-课外1比1）的开发工作量计算
- 项目分工：以下形式均可
  - 一个项目，多个模块，各模块可分工开发，但需要集成才能运行。优点是各人各尽所长，缺点是需要有较强的项目管理和团队管理能力，局部的失败可能导致整个项目失败。
  - 一个主题，多个独立运行的子项目。子项目之间围绕主题，互通互联和互相协作。优点是各负各责，弱耦合。缺点是对每个人的技术要求较全面
  - 上述两种方式的混合，可按团队实际情况出发。

## 立项过程

- 开课前一周，线下或群里发布题目、寻找队友，自行组队
- 第一天课上：由各小组依次进行立项汇报和答辩。通过并整改后正式立项
- 第二天课前：提交整改后的立项报告

## 立项文档

- 题目：即项目名称
- 摘要：不超过200字的摘要，回答：
  - 为什么：为什么做：为什么：为谁服务？为何要解决这个问题？用户价值、技术价值或社会价值是什么？
  - 做什么：解决什么问题？有哪些具体的功能目标、技术目标？
  - 怎么做：基于什么理论？采用哪些技术？用了哪些工具？
- 调研：对同类产品或技术项目的网络调研，一般应列举至少三个，并进行功能、技术等层面的对比和评述。
- 需求列表：采用用户故事或原型图等方式，列举出项目的主要或核心的功能点
- 技术方案：拟采用的系统架构、开发平台及语言、开发框架及库、开发环境及运行环境、项目管理工具等
- 团队分工与任务：各成员的团队角色及其任务列表，要求每人独立维护一个git库，具体的任务划分可按如下：
  - 可按技术模块划分：如前端、后端、算法、运维等
  - 可按项目的层次分：如产品、开发、测试、运维等
  - 也可混杂，关键是，每个人都有足够的工作量和成果
- 项目开发计划：从V0.1 到 V1.0 的版本发布计划，并给出至少三个里程碑点，对应于概念验证、中期检查、项目验收等三个检查点
  - 可参考 https://github.com/vuejs/vitepress/blob/main/CHANGELOG.md
- 可行性分析：
  - 技术可行性：结合团队各成员的过往项目基础、技术基础等进行讨论
  - 团队可行性：讨论如何保证团队成员能高效协同的各项措施，如内部纪律、会议沟通、代码审查、源代码管理等

> 以上文档不要求在立项时一步到位，但立项时应具备基础框架。后续可在实际开发过程中进行迭代和重构，最终汇入期末的项目报告中

## 立项答辩

- 准备立项文档（初稿）及相关佐证材料
- 组长对项目做整体说明，并介绍自己，论证项目的可行性
- 各成员依次介绍自己的角色和任务列表，介绍自我特长、项目经历等，证明能胜任其职。
- 教师提问及评述
- 总时长控制在10分钟之内
