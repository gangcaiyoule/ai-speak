# 思政报告

> **项目名称**：SpeakUp：基于 Flutter 与 Go 的 AI 英语口语陪练系统
> **报告人**：陈冠亨（学号 24320121）
> **负责模块**：AI 对话与实时语音链路（voice_stream）

## 一、个人、集体与国家三位一体（融入点 1）

本项目让我第一次真切体会到「个人成长嵌入集体目标、集体成果回应社会需求」的路径。我负责的实时语音链路，单独看只是采集、传输、播放三条数据通路，但它只有嵌入团队的口语陪练系统才有意义——我的环缓、切帧、会话状态机如果脱离队友的练习会话和评测模块，就只是没有用户的底层库。六天里我多次为了让合并后的整体可用而调整自己的接口：比如把客户端 HTTP 统一改为 `package:http` 以配合队友模块的 web 打包，比如主动审计全链路找出练习会话接线的缺口并当面同步给队友，而不是只顾自己模块的「技术洁癖」。

从更大的坐标看，缺少真实英语表达环境是许多国内学习者共同的痛点，市面产品要么价格高昂、要么缺少针对技术面试等本土场景的训练闭环。用自己掌握的工程技术为这个真实需求做一点增量，就是把个人发展与社会需求、国家语言能力建设结合起来最朴素的方式。做这个项目也让我明确了方向：毕业后继续在跨端音视频与实时系统方向深耕，把个人职业规划落在国家软件产业真正需要的底层能力上。

## 二、爱国、诚信、敬业、友善（融入点 2）

**爱国——正视差距，激发科技报国的决心。** 立项阶段我们对比了 Speak、ELSA Speak、Duolingo Max 等国际领先产品。它们的实时语音交互、音素级反馈确实领先，这让我清醒地看到差距：尤其在移动端低延迟音频这一层，Oboe、AAudio、WebRTC 这些经过大流量验证的弱网基础设施，核心生态仍在国外厂商与开源社区手中。但分析差距不是为了气馁，而是为了找准发力点——我在模块里坚持「传输不造轮子、缓冲与状态机自研可控」的策略，把最影响体验的端上实时链路牢牢握在自己手里。这种「底座自研、生态借用」的思路，是我理解的技术自立。

**诚信——数据与结论不掺假。** 我给自己定了硬规矩：没跑过的验证一律不写「已通过」。本机没有 Flutter SDK 的三天里，日报里明确写「客户端检查未执行」，而不是含糊其辞；所有测试结果都署名具体环境（哪个 Codespace、哪个 SDK 版本）。最有代表性的一次：AI 声称环形缓冲设计参考了 Oboe 官方的 `FifoBuffer.h`，我核对官方仓库确认该文件根本不存在，当即要求它撤回，改用可核对的官方回调纪律作为设计依据。对 AI 的输出尚且如此，对他人的成果更不会含糊——基于上游开源代码的部分在立项文档中明确声明，自研增量与复用边界写得清清楚楚。

**敬业——从小事做起，服从团队安排。** 课程只有六天，我没有挑「看起来高级」的活，而是把修编译错误、统一注释为 Doxygen 格式、写提交辅助脚本、清理占位文件这类小事逐件做扎实。D6 全队收尾阶段，我的提交是给服务端加 web 静态托管以便同源演示——不是新功能，而是让整个项目能顺利交出去的那「最后十六行」。

**友善——互帮互助，共同进步。** 我把踩坑整理成可复用的文档：Codespaces 环境搭建指南（含 Windows scp 需加 `-O` 这类具体坑）供全队使用；主动帮队友审计服务端接口打通情况，用实测数据指出最高优先级缺口，而不是停留在「我觉得」。

## 三、团队协作与沟通（融合点 3）

四人并行开发一周，协作成本是最大风险。我的做法是**契约先行**：开工第一天先定下 `MicSource`、`AudioSink`、`AudioTransport` 五大抽象和会话层语义，队友模块只依赖契约，平台实现随时可换，这是我们能并行而不互相阻塞的关键。沟通上坚持「当面同步、留痕落库」：重要结论当天写进日报和文档，夜间提交次日逐一补记 hash 消除悬空，发现的跨模块问题当面口头同步优先级、文档里只写可公开的结论。过程中也有分歧——比如我的流式链路与队友的三段式语音方案如何并存，最终通过「契约不变、装配层换实现」达成一致，而不是争论谁的技术路线更优。这段经历让我理解了职业协作里「对事不对人、用证据说话」的分量。

## 四、精益求精的工匠精神与系统性思维（融合点 4）

实时音频是容不得「差不多」的领域：采集回调线程一次 malloc 就可能断音，一次未加保护的指针就可能野指针崩溃。这个模块逼着我把严谨变成习惯：

- 追每一个根因而非现象。播放欠载断音，表象是「网不好」，根因是缺少迟滞机制，解法是在播放队列里实现 60ms 阈值起播；Oboe 独占模式崩溃，根因是低配设备不支持，解法是捕获返回值自动降级共享模式。
- 用测试锁定语义而非靠记忆。环缓 9 个用例、切帧 32 个用例、状态机 12 个用例、播放队列与 FFI 绑定合计四百余行单测，每次修 bug 先补一个能复现的用例，再修到全绿。
- 系统性地看问题。web 打包一连串编译错误（`dart:ffi` 缺失、`unsafeCast` 被移除、`dart:io` 不可用），我没有逐个打补丁，而是从「平台差异应收敛在装配层」出发，一次性重构出平台工厂加条件导入的结构，让同类问题不再发生。

这种「从系统角度消灭一类问题」的思维方式，是这六天里工匠精神给我最具体的训练。

## 五、诚信独立、实事求是（融合点 5）

本报告与设计报告由本人独立撰写，所有技术事实、测试数据均来自我的日报、提交记录与真实执行过的验证命令，未运行过的项目（浏览器 getUserMedia 实测、真机延迟实测）如实标注为待执行，绝不虚构「已通过」。代码方面，团队基于既有开源基线做增量开发，我在立项与设计报告中逐项区分了上游复用与自研实现，引用他人设计与文档均标明出处。我认为实事求是不只是不抄袭，更是对自己能力的诚实：会就是会，没验证就是没验证，这份诚实是工程师生涯里最不能让步的底线。
