## 一、个人负责模块与立项背景

本项目面向缺乏真实英语表达环境的学习者，打造包含模拟面试、IELTS 与职场对话的 AI 陪练系统。在团队分工中，本人（陈冠亨，24320121）独立负责 **AI 对话与实时语音链路模块（`voice_stream`）**。

实时语音是本产品体验的核心瓶颈。传统移动端音频采集常面临三大痛点：
1. 原生平台通道（Platform Channel）传输音频带来频繁跨进程与数据拷贝开销，延迟高；
2. 移动端音频采集线程属于高优先级硬实时线程，执行耗时操作（malloc、锁、I/O）极易引发卡顿或断音；
3. 弱网环境下客户端积压易造成延迟累积，缺少可控的丢包与丢帧补偿策略。

## 二、技术架构与关键方案

为解决上述痛点，本人在 `voice_stream` 模块中确立了以下技术路线：

1. **接口先行与轻量抽象（Dart）**：
   在 `src/contracts.dart` 中定义 `AudioFormat`、`AudioFrame`、`MicSource`、`AudioSink`、`AudioTransport` 五大核心契约，UI 仅依赖抽象接口，平台底层可透明替换。
2. **跨平台 C 底层与零拷贝环缓**：
   - 核心缓冲与采集采用 C/C++ 实现，一份代码双端复用（Android NDK / iOS Xcode 原生编译）；
   - 自研单生产者单消费者（SPSC）无锁环形缓冲，采用 acquire/release 原子序；
   - 确立“生产者永不阻塞”原则：容量不足时自动覆旧并累加 `droppedBytes` 计数，作为端上唯一的弱网降级出口；
   - 消费端暴露只读内存视图（`peek()`/`advance()`），强制同步成对调用，实现零拷贝消费。
3. **定长切帧与帧头编解码**：
   按 20ms 时间窗（16kHz/16bit/单声道 = 640 字节）切分定长帧，设计 12 字节紧凑帧头（seq + timestamp + size + flags），通过 `flags` 主动标记丢包空洞。
4. **WSS 实时流式回声链路与会话状态机**：
   - 客户端基于 `WssEchoTransport` 实现全双工传输，服务端在 Go (Gin) 下建立 `/ws/voice/echo` 端点；
   - 在传输之上叠加会话层（`TransportVoiceSession`），实现严格的生命周期状态流转与幂等键校验。
5. **云端自动化测试闭环（GitHub Codespaces）**：
   针对本地开发机缺乏环境的痛点，构建预置 Flutter 3.47.2 与 Go 1.22 的云端开发容器，建立标准测试流水线，已实现 32 个单元测试全绿。
