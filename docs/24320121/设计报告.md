## 一、项目概述与个人分工

SpeakUp 是一个面向缺乏真实英语表达环境学习者的 AI 口语陪练系统，采用 Flutter 跨端客户端 + Go/Gin 后端 + PostgreSQL 的全栈架构，提供模拟面试、IELTS、职场与生活场景的语音对话练习、即时反馈与同题复练。

本人在团队中独立负责 **AI 对话与实时语音链路模块（voice_stream）**，覆盖从麦克风采集、分帧、上行流、服务端识别评测、流式回包到端上低延迟播放的完整数据通路。该模块只关心「读（采集）、传（上行/回包）、放（播放）」三条通路及其抽象，字幕、波形等 UI 只预留数据出口，由团队其他成员的练习模块消费。

模块硬约束：

- 采集与 UI 线程互不阻塞，实时音频回调线程内禁止锁、阻塞与动态内存分配；
- 可随时中断与重连，会话生命周期状态明确；
- 弱网下有明确的缓冲与丢帧策略，延迟不随网络抖动无界累积。

## 二、需求与约束分析

实时语音是本产品体验的核心瓶颈。立项阶段分析了传统移动端音频方案的三大痛点：

1. **Platform Channel 高开销**：常规插件经 Platform Channel 搬运音频，频繁跨线程拷贝，延迟高、吞吐受限；
2. **实时线程纪律**：移动端采集回调是高优先级硬实时线程，执行 malloc、锁、I/O 等耗时操作会直接卡顿断音；
3. **弱网延迟累积**：客户端缓冲积压导致延迟单调增长，且缺少可控的丢包/丢帧补偿出口。

由此确立设计原则：**接口先行、纯逻辑可单测、平台实现可替换、采集线程永不阻塞**。全部纯逻辑（环缓、切帧、会话状态机）用 Dart/可单测实现先行验证，平台相关代码（Oboe/RemoteIO/浏览器）只做被替换的「装配件」。

## 三、总体架构设计

模块按「契约层 → 纯逻辑层 → 平台实现层 → 装配层」组织：

```text
┌─────────────────────────── Flutter (Dart) ───────────────────────────┐
│  UI/控制器（只依赖抽象契约，不感知平台）                                │
│      │                                                               │
│  契约层 src/contracts.dart                                            │
│    AudioFormat / AudioFrame / MicSource / AudioSink / AudioTransport  │
│      │                                                               │
│  纯逻辑层（全部可单测）                                                │
│    ring_buffer.dart(参考实现)  frame_slicer.dart  session.dart        │
│      │                            │                │                  │
│  会话适配 session_transport.dart：Transport ↔ VoiceSession 状态机      │
│      │                                                               │
│  平台工厂 mic_source_factory.dart（条件导入 io/web/stub）              │
│   ├─ 原生：NativeMicSource / NativeAudioSink（dart:ffi 控制面）       │
│   │    └─ 统一 C ABI voice_input.h / voice_output.h                   │
│   │        ├─ Android：Oboe 输入/输出流（C++）                        │
│   │        └─ iOS：RemoteIO 采集/渲染（C + 约20行 ObjC++ 会话壳）      │
│   │        └─ C 共享层：spsc_ring_buffer.h / playback_queue.h         │
│   └─ Web：WebMicSource（getUserMedia + AudioWorklet）+ pcm_convert    │
│      │                                                               │
│  传输层 wss_echo_transport.dart ──WSS──► Go 服务端 /ws/voice/echo     │
└───────────────────────────────────────────────────────────────────────┘
```

语言与平台决策：

| 层 | 语言 | 理由 |
|---|---|---|
| 采集/播放/缓冲 | C（Android 侧 C++，因 Oboe） | 一份实现两端编：NDK 编进 Android，Xcode 直接编进 iOS |
| iOS 会话激活 | Objective-C++ 壳（约 20 行） | `AVAudioSession` 激活是 iOS 规定动作，AudioUnit 本身是 C API |
| Dart 侧 | `dart:ffi` 控制面 + 数据出口 | 只拿指针、调开关，不做数据搬运 |
| web 采集 | Dart（`package:web`） | 浏览器无 `dart:ffi` 与原生库，走 getUserMedia + AudioWorklet |
| 服务端 | Go（仓库既有骨架） | 复用现有 Gin + WebSocket 基础设施 |

## 四、核心方案、算法与数据结构设计

### 4.1 SPSC 无锁环形缓冲（核心数据结构）

两端平台差异（Oboe 回调 vs RemoteIO 回调）全部消化在同一份 C 缓冲实现 `native/spsc_ring_buffer.h` 中，Dart 参考实现 `src/ring_buffer.dart` 与之语义逐条对齐：

- **单生产者单消费者（SPSC）无锁**：生产者是音频回调线程，消费者是 FFI 侧读取，仅两个指针，C 层用 acquire/release 原子序保证跨线程可见性，全程无互斥锁；
- **生产者永不阻塞**：容量不足时覆盖最旧数据（丢旧）并累计 `dropped_bytes` 计数。这是端上唯一的弱网/背压降级出口——上层只看计数，不感知缓冲内部状态，延迟因此有界；
- **零拷贝读**：`peek()` 返回内部存储的只读视图，`advance(bytes)` 后该区间才可被覆盖。约束为 peek/advance 必须同步成对调用，不得异步持有视图（丢旧会推进读指针，覆盖未提交区间）；
- **容量按毫秒预算**：构造时传入，如 16kHz × 16bit × 单声道 × 1000ms = 32KiB，缓冲规模与延迟预算一一对应。

同一组单测（往返、回绕、溢出丢旧、丢帧计数、peek/advance 配对，共 9 个用例）先在 Dart 参考实现上转正，再在 NDK/Xcode 下回归 C 实现，保证双端语义一致。

### 4.2 定长切帧与帧头协议

采集吐出的是任意长度字节块，`src/frame_slicer.dart` 按 20ms 时间窗（16kHz/16bit/mono = 640 字节）切成定长帧，帧头 12 字节小端序：

```text
uint32 seq; uint32 timestamp_ms; uint16 size; uint16 flags;
```

丢帧观测采用「主动标记 + 被动跳号」互补设计：上游（环缓丢旧/采集断流）drop 后，切帧器把 `gapBefore = 0x0001` 打在下一帧 `flags` 上，这是发送方**主动**标记；接收方按 `seq` 跳号被动观测丢帧。两者互为校验，服务端据此估算丢包率与空洞位置，避免「静默丢失」不可见。

### 4.3 传输选型与会话状态机

传输不自己造轮子，先做选型对比：

| 方案 | 适用 | 结论 |
|---|---|---|
| WSS 云服务协议 | 对接云厂商实时语音 API（ASR/LLM/TTS 融合在一条 WebSocket） | **主推**：集成最快，弱网靠端上环缓丢帧兜底 |
| WebRTC | 自建媒体网关（Pion/LiveKit），ICE/SRTP/jitter buffer 现成 | 备选：弱网实测不达标或需自托管时启用 |
| 自管 UDP+KCP | 完全自托管且需手调重传参数 | 后备，不启用 |

在传输之上叠加会话层 `src/session.dart`，生命周期严格单向：

```text
idle → active → (finish → 等服务端 final/failed 终态 | cancel) → closed
```

- **幂等键**：`VoiceSessionConfig.idempotencyKey`（8–128 字符），同一逻辑会话跨重连重试保持不变，服务端据此去重，杜绝重连导致的重复计费/重复识别；
- **事件模型**：`SessionStarted / SessionPartial / SessionFinal / SessionFailed(kind, retryable) / SessionStats`，partial/final 区分支撑流式字幕；
- **失败模型**：失败带 `kind` 与 `retryable`，`retryable=true` 时用同一幂等键重开；终态后不可复用，重试须新开会话，杜绝状态泄漏。

### 4.4 播放队列与欠载迟滞（R7）

网络抖动下回包忽快忽慢，直接播放会「抽空断音」。`native/playback_queue.h` 设计无锁播放队列：

- **迟滞起播（Hysteresis）**：缓冲积攒到阈值（如 60ms）才起播；欠载抽空后不立即续播，而是重新积攒到阈值再播，把网络抖动平滑在缓冲层，代价是每次欠载后固定一次阈值时长的停顿，远优于逐包断音；
- 双端渲染底座：Android `voice_output_oboe.cpp`（Oboe 输出流）与 iOS `voice_output_ios.mm`（RemoteIO 渲染单元），统一收敛到 C ABI `voice_output.h`，Dart 侧 `NativeAudioSink` 只做 FFI 动态绑定。

### 4.5 跨平台装配与 web 支持

平台装配采用**条件导入 + 平台工厂**双解耦：插件绑定层 `bindings.dart`（原生 FFI ↔ web 桩）与模块工厂 `src/mic_source_factory.dart`（NativeMicSource ↔ WebMicSource）都用两分支同名导出的 `createDefault*Bindings()` 工厂收敛，下游代码只引用工厂符号。App 装配层注册 `/voice-debug` 调试路由，web 打包后在浏览器授权麦克风即可实测采集链路。web 侧 Float32→I16 采样转换抽为纯函数 `src/pcm_convert.dart` 单独单测。

## 六、出现的问题、原因分析与解决方法

开发全程采用「问题—原因—解决」记录，以下是代表性踩坑：

| 问题 | 根因 | 解决方法 |
|---|---|---|
| AI 初始设计假设采样率固定 | 查阅官方文档：iOS 采样率是请求而非保证，Oboe `getTimestamp()` 在 OpenSL ES 回退下不可用 | 接口改为按协商交付（`AudioFormat` 值对象），低端机用本地单调时钟 |
| peek/advance 异步持有会读到被覆盖数据 | 覆旧策略推进读指针，未提交视图可能失效 | 契约层面约束两操作同步成对调用，单测固定该语义 |
| 会话层并发缺陷：waiter 空断言、超时重复完成 | 状态机竞态路径未被覆盖 | 补 12 个状态机测试精确定位后修复 |
| `stop()` 阻塞未订阅的流 | 停止逻辑等待无人消费的事件 | 修正停止时序，同步修正 gap 测试的时序假定 |
| Oboe 独占模式低配设备崩溃 | 部分设备不支持 Exclusive 直接 open 抛错 | 捕获返回值自动降级 Shared 共享模式重试 |
| iOS 停止播放野指针风险 | 主线程关闭 AudioUnit 与实时渲染回调存在竞态窗口 | 壳层加状态原子标志与安全排空 |
| 欠载断音 | 回包稍延迟缓冲即抽空 | playback_queue 迟滞起播机制 |
| web 上 `dart:ffi` 不存在，绑定构造即抛错 | 浏览器无原生库 | FFI 符号查找改惰性 `late final` + 平台工厂 |
| 下游引用分支专属导出名编译失败 | 条件导入后导出名下游不可见 | 两分支收敛同名工厂导出 |
| `unsafeCast` 在新 SDK 被移除 | Dart 3.13 移除该 API | 改为 JS 类型 as 转换 |
| web 上 `dart:io HttpClient` 不存在 | 客户端直连代码依赖 io | 统一改 `package:http`（web 走 fetch，原生走 socket） |
| 本机无任何工具链，测试无法执行 | Windows 环境缺 Flutter/Go/Docker | Codespaces 预打 SDK 镜像 + sshd feature，建立云端验证闭环（另见 [codespaces-flutter-setup.md](./codespaces-flutter-setup.md)） |

其中最典型的一个过程：AI 曾声称环缓设计参考了 Oboe 的 `FifoBuffer.h`，经核对 Oboe 官方仓库确认该文件不存在，当即要求 AI 撤回该虚构依据，改以 Oboe 官方回调纪律（禁锁、禁 malloc、禁阻塞）作为无锁设计的真实依据。此事促使我在后续协作中确立「AI 结论必须给出可核对出处，否则不落入文档」的规则。

## 七、创新点总结

1. **「生产者永不阻塞」的丢旧式 SPSC 无锁环缓**：以覆旧 + `dropped_bytes` 计数作为弱网降级唯一出口，把「缓冲管理」与「延迟控制」合并为同一机制，实时回调线程零锁零分配，且一份 C 实现双端复用、Dart 参考实现同语义可单测；
2. **12 字节紧凑帧头 + 主动/被动互补丢包观测**：`flags.gapBefore` 发送方主动标记丢帧空洞，与 `seq` 跳号被动观测互为校验，在极小的协议开销内给出可靠丢包估计；
3. **幂等键 + partial/final + kind+retryable 的会话状态机**：弱网断线重连不产生重复会话，失败可分类重试，终态不可复用保证状态不泄漏，为流式打断与多轮上下文预留完整语义；
4. **播放迟滞起播欠载状态机**：以 60ms 阈值迟滞平滑网络抖动，用确定性的固定停顿替换不确定的逐包断音；
5. **平台工厂 + 条件导入的第三端复用**：同一套契约不经修改扩展到 web（getUserMedia + AudioWorklet），原生行为零回归，验证手段为 web 编译图覆盖检查。

## 八、改进思路与展望

- **R8 弱网与真机联调**：注入延迟/丢包，用实测数据回溯 60ms 迟滞阈值的取值依据，补齐回环延迟实测；
- **真实云链路接入**：R6 回声链路已验证协议与会话层，下一步接入云厂商实时语音 API，验证 partial 回流与打断延迟；
- **播放策略细化**：迟滞阈值随网络抖动估计自适应调整，替代固定 60ms；
- **浏览器运行时自动化测试**：当前 web 用例受容器无浏览器限制未跑，计划补 `--platform chrome` 用例；
- **与三段式链路并存**：队友的「录音→ASR→LLM→TTS」三段式作为功能兜底，本模块瞄准流式升级路径；契约不变、装配层换实现，AudioSink 的迟滞起播可直接复用于 TTS 分块回包的平滑播放。
